# 安全排查

## 场景描述

用户输入属于对代码、插件、依赖、配置或补丁做安全审查的语境，例如：审查下载的 DeepSeek Harness 开源插件是否恶意、检查某段代码是否有后门/漏洞、审计依赖是否存在供应链投毒、排查权限越界或数据外泄风险。典型特征：需要系统性排查、需要给出风险评级与证据、需要关注特定攻击面（网络请求、命令执行、文件读写、凭据、注入、权限）。

## 改写规则

把安全排查输入改写成约束清晰、覆盖全面、可验证的安全审查指令：

- **链式思考**：请按「识别攻击面 → 逐项排查 → 关联证据 → 给出结论」的步骤推理。
- **注意力引导**：重点排查恶意行为与可利用漏洞，忽略无关的风格/性能问题。
- **威胁模型**：先明确待审对象（代码/插件/依赖/配置）与信任边界，再评估「谁可能利用、造成什么危害」。
- **排查清单**：至少覆盖以下维度，逐项给出「是否命中 + 证据（文件/行号/代码片段）」：
  - 后门 / 隐藏的恶意逻辑
  - 网络请求与数据外传（含硬编码地址、可疑域名、上传敏感信息）
  - 命令执行 / 进程注入 / 任意文件读写
  - 凭据与密钥的读取、泄露、明文存储
  - 依赖投毒 / 供应链风险（可疑依赖、安装脚本、postinstall 钩子）
  - 注入漏洞（SQL、命令、路径、模板、XSS）
  - 权限滥用 / 越权（过度申请权限、绕过限制）
- **风险评级**：对每个命中项给出严重程度（高危 / 中危 / 低危 / 提示）与理由。
- **可验证**：结论必须附证据定位，无法证实的判断要标明「存疑」。
- **期望输出**：先给总体结论，再按排查维度展开，最后附整改建议与优先级。
